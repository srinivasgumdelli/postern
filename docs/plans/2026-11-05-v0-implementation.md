# Postern v0 Implementation Plan

> For agentic workers: implement task-by-task. Steps use checkbox (`- [ ]`) syntax. Do not run git; the coordinator commits.

**Goal:** Build v0 as specified in DESIGN.md and PLAN.md: bridge binary (MCP server, crypto, keychain, inbox), relay (Docker, behind a tunnel), edge setup docs, and the session-side guard, with a test for every security property.

**Architecture:** Each agent session that should use Postern launches `postern mcp --session NAME` over stdio. That process loads keys from the OS keychain, polls the relay, and shares one SQLite inbox per machine with any other Postern processes (WAL, dedup by message id). There is no long-running daemon. The relay is a small Go HTTP service that stores ciphertext and binds every request to the peer named by the client certificate.

**Tech stack:** Go 1.26, stdlib first, `golang.org/x/crypto/nacl/box`, `modernc.org/sqlite` (pure Go), `github.com/modelcontextprotocol/go-sdk`, macOS Security.framework via cgo (bridge only), Docker Compose (relay + cloudflared).

**Spec:** `DESIGN.md`, `PLAN.md`.

## Global constraints

- Module path `postern`. Go 1.26. Packages under `internal/`, binaries under `cmd/`.
- Dependencies limited to: `golang.org/x/crypto`, `modernc.org/sqlite`, `github.com/modelcontextprotocol/go-sdk`. Nothing else without coordinator approval. Do not edit `go.mod`/`go.sum`.
- Generic names only: `peer-a`, `peer-b`, `machine A/B`, `operator`, `postern.example.com`. No real names, hostnames, domains or paths.
- Never log message subjects, bodies, keys, certificates or query strings. Logs use `log/slog`.
- Keys never in files or env vars. Production secret storage is the OS keychain only; the in-memory store lives in a test-only package.
- Limits (exact): body 32768 bytes, subject 256 bytes, encoded envelope 49152 bytes, clock skew 10 minutes, retention 72 hours, long-poll timeout max 25 s.
- Peer and session names match `^[a-z0-9][a-z0-9-]{0,31}$`. Thread ids match `^t-[0-9A-HJKMNP-TV-Z]{26}$` and are generated by the bridge only.
- Inbound content is always presented with `origin=external`, `trust=untrusted`.
- Every test runs with `go test ./...` and needs no network, no Docker and no keychain (keychain tests are gated by `POSTERN_TEST_KEYCHAIN=1`).

## Hosting decision

The relay runs locally in Docker on machine A behind the tunnel (operator decision). The review asked for a Cloudflare Worker + Durable Object so the relay is always on; that is deferred. While machine A is off, messages wait in the sender's outbox and retry. The relay API is host-neutral, so a Worker can replace or front it later without bridge changes.

## Gap fixes (decided; DESIGN.md updated to match)

1. **Identity binding moves into v0.** The relay maps the client certificate SHA-256 fingerprint to a peer name and rejects any `from` (post) or `to` (poll, ack) that is not that peer. In production the edge forwards the fingerprint in `X-Postern-Client-Cert-Sha256` (a transform rule that sets the header, overwriting anything the client sent); in tests and dev the relay terminates mTLS itself and computes the fingerprint.
2. **Replay window moves into v0.** The relay rejects envelopes whose `ts` is more than 10 minutes from its clock and remembers ids for 72 hours (409 on repeat). The bridge reseals queued messages with a fresh `ts` on every retry, keeping the same id.
3. **Taint does not clear on just any prompt.** It is set before `check_inbox` runs (pessimistic), dropped only if that call returned zero messages, and otherwise cleared only when the human submits the exact prompt `postern clear`. While tainted, every tool except `check_inbox` and `mark_read` asks; in bypass or unknown permission modes it denies. Malformed hook input asks.
4. **Routing fields are authenticated.** The sealed inner message repeats `v, id, from, to, thread, ts`; `Open` rejects any mismatch with the outer envelope. `from` must be a pinned peer and `to` must be self.
5. **Config pin.** The bridge stores the SHA-256 of its config file in the keychain and refuses to start if the file changed (relay URL, peer keys, sessions) until the human runs `postern config pin`.
6. **Keychain items are created in-process** (Security.framework), so the item ACL trusts only the bridge binary; `security find-generic-password` from another process triggers a macOS prompt.
7. **Secret scanner in v0 (review feedback).** `send` and `reply` are blocked, not redacted, when subject or body looks like a private key, token or credential assignment. Encryption does not help if a session pastes a secret into a reply, and a human approving a long reply will not read every line. The error names the rule and line only, never the match.
8. **Codex uses `approval_policy = "untrusted"` only** (review feedback). With `on-request` the model decides when to ask, so an injection can talk it out of asking.
9. **Taint also clears on a fresh context.** A `SessionStart` hook with `source = "clear"` drops the marker; `compact` and `resume` keep it. The human can also clear it with the `/postern-clear` command (shipped with `disable-model-invocation: true`) or the exact prompt `postern clear`.
10. **Residual risk, documented, not fixed in v0:** any process running as the same OS user can run the `postern` binary itself. Separate OS users for the bridge are a v1 option.

## Review focus

1. A 32 KB body full of quotes, newlines, backslashes and `<>` must still seal under the 48 KB envelope cap (inner uses a length-prefixed header + raw body, not JSON-escaped body). Test: `TestSealWorstCaseBodyFitsEnvelopeCap` (Task 1).
2. Relay offline longer than 10 minutes with messages queued: retries must reseal with a fresh `ts` and get delivered, not rejected as stale. Test: `TestOutboxResealsAfterStaleWindow` (Task 5).
3. Two Postern processes on one machine polling the same relay mailbox: no duplicate inbox rows, no `SQLITE_BUSY` surfaced. Test: `TestTwoBridgesShareInboxNoDuplicates` (Task 5).
4. Bodies with a fake end delimiter, ANSI escapes or "ignore previous instructions": framing stays intact, control characters stripped, tags present. Test: `TestCheckInboxFramingResistsDelimiterAndEscapes` (Task 6).
5. Hook input drift (missing fields, unknown `permission_mode`, non-JSON): guard fails closed. Tests: `TestPreToolUseMalformedInputAsks`, `TestPreToolUseUnknownModeDenies` (Task 7).
